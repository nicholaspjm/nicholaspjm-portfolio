# SEO

What is in place, where it lives, and what still needs doing by hand.

## The one thing to understand first

Every push to `main` publishes the **same HTML to two hosts**: GitHub Pages
(`nicholaspjm.github.io/nicholaspjm-portfolio`) and Cloudflare. Two identical
copies of a site compete with each other in search results unless you tell
Google which one counts.

Every page therefore declares a canonical URL on `nicholaspjm.com`, built from
`site.url` in `src/content/site.ts`. The mirror serves the same tag, so it
points at the domain too, and the domain collects the credit for both.

Canonical is used rather than `noindex` on the mirror deliberately. Google
treats the two as conflicting signals, and a `noindex` mirror would currently
remove the *only* live copy of the new site from search — the domain still
serves the old Cargo site until the move in `DOMAIN-TRANSFER.md` is done. Once
the domain is live and indexed, noindexing the mirror is a reasonable
follow-up, but it is not needed.

## What ships automatically

| Thing | Where |
| --- | --- |
| Canonical, OG and Twitter tags | `src/lib/seo.ts` → `pageMeta()`, called by every page |
| Title template, keywords, robots directives | `src/app/layout.tsx` |
| `sitemap.xml` (31 URLs) | `src/app/sitemap.ts` |
| `robots.txt` | `src/app/robots.ts` |
| `Person` + `WebSite` JSON-LD | `src/components/layout/structured-data.tsx`, rendered in the layout |
| `CreativeWork` JSON-LD per project | same file, rendered by `work/[slug]/page.tsx` |
| Per-project share cards | `scripts/make-og-images.mjs`, run by `prebuild`/`predev` |

Both route files carry `export const dynamic = "force-static"` — `output:
"export"` refuses to build a route handler without it.

## Share cards

- **`public/og-default.png`** is the site card, used by every page without an
  image of its own. It is **committed**, and regenerated by hand:

  ```
  npm run og-default
  ```

  It draws text, and the CI runner is Ubuntu with neither Arial nor Courier
  New — a card built there would silently come out in a substitute face. Build
  it on a machine with the site's fonts and commit the PNG.

- **`public/og/<slug>.jpg`** is one 1200x630 crop per project, generated from
  the first still that project shows, and **not** committed (see
  `.gitignore`). Adding a project with images gets it a share card with no
  extra step. A project with no still — video- or embed-led work — falls back
  to the site card.

Cropping at build time rather than handing platforms the raw image matters: a
portrait still linked as-is gets centre-cropped by whoever renders it, usually
through the middle of the subject.

## Headings

Every page has exactly one `<h1>`. The section labels ("index of work",
"about", "colophon") *are* those headings — promoted from `<span>`, wrapped in
`.labelrow` so they keep the paragraph rhythm they replaced, with the yellow
`.extra` highlight still on an inline span inside so it hugs its text instead
of stretching the full width.

The index has no visible title, so its `<h1>` is `sr-only`: present for
crawlers and screen readers, invisible on screen.

Note that a heading may not live inside a `<p>` — the HTML parser closes the
paragraph and React throws a hydration error. If you add a label, make the
wrapper the heading.

## Vocabulary

`site.keywords` and `site.alsoKnownAs` in `src/content/site.ts` are the source
of truth for what the site should be found by. They feed `<meta keywords>` and
JSON-LD `knowsAbout`/`alternateName`, and page descriptions draw on the same
vocabulary. `site.tagline` is never rendered on screen — it is the meta
description, written to fit a search result in under ~160 characters.

## Still to do by hand

1. **Move the domain.** Everything above names `nicholaspjm.com`, which still
   serves the old Cargo site. See `DOMAIN-TRANSFER.md`.
2. **Google Search Console.** Add `nicholaspjm.com` once it resolves to this
   site, and submit `https://nicholaspjm.com/sitemap.xml`. The domain already
   carries a `google-site-verification` TXT record, so verification should
   pass immediately. Nothing gets indexed on a schedule you control until
   this is done.
3. **Cloudflare Web Analytics.** Cloudflare dashboard → *Web Analytics* → add
   `nicholaspjm.com`. Free, cookieless, and needs no consent banner, which is
   why `gaId` in `site.ts` is deliberately left empty. Only works once the
   domain is proxied through Cloudflare, so do it after step 1.
